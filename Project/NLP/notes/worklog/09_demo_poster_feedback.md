### 업무 내용

#### Motivation

생성 모델의 한계점

- 생성 모델은 train data에 대한 패턴을 제외한 질문에는 적절하게 답변하지 못한다.

해결방안

- 검색 기반 모델을 통해 추가적인 지식을 수집하여 정확도와 풍부한 답변을 가능하게 했다.
- 또한 배우라는 특성에 맞는 Prompt Engineering을 진행해 특성을 살릴 수 있는 답변을 만들겠다.

프로젝트 목표

- RAG 를 통해 질문에 정확히 답변하게 구현하겠다.
- 효율 적인 Prompt를 제작해 답변의 정확도를 높이겠다.

#### Introduction

Prompt Engineering

- 생성형 AI에 솔루션을 안내하여 원하는 결과를 생성하는 프로세스
- 입력하는 텍스트는 Prompt라 불리며 이의 구성요소는 Instruction, Context, Input, output data가 존재함
- 최적화된 Prompt를 찾아 높은 결과를 생성하는 것이 목표

RAG

검색 기반 모델 프로세스

- 미리 수집된 대규모의 외부 지식 그래프 이용
- 입력 문장과 연관성 있는 정보 추출
- 위에서 추출된 정보를 이용하여 생성 모델의 input으로 사용하여 응답 생성

소개

- 대량의 외부 데이터 소스로부터 정보를 검색하는 검색 모듈과 생성 모델을 이용하여 검색된 정보를 활용하여 새로운 콘텐츠를 생성
- 검색 모듈 + 생성 모델

> ✍️ **Feedback**
>
> 사전 학습된 언어 모델을 활용하여 특정한 태스크를 수행하도록 하는 방식은 크게 두 가지가 있습니다. 하나는 파인튜닝(fine-tuning)이며 다른 하나는 프롬프트 엔지니어링(prompt engineering)입니다.
>
> 최근에는 언어 모델의 규모가 거대해져 개인이 직접 파인튜닝을 수행하기 어렵습니다. 반면 프롬프트 엔지니어링은 많은 GPU 자원을 요구하지도 않으며, 언어 모델이 수행해야 할 지시문을 잘 작성하는 능력만을 요구한다는 점에서 기술적인 진입장벽도 높지 않습니다.
>
> 이러한 장점 때문에 프롬프트 엔지니어링은 현재 활발하게 연구되는 분야입니다. 언어 모델은 이미 엄청난 양의 지식을 보유하고 있습니다. 따라서 추가 학습이 이루어지지 않아도 그 지식을 잘 활용하는 가이드만 주어진다면 명시적으로 학습하지 않은 일을 잘 수행할 수 있습니다. 프롬프트는 언어모델에 지시를 내릴 때 사용하는 텍스트를 의미합니다. 결국 프롬프트 엔지니어링은 언어모델이 새로운 일을 잘 수행할 수 있도록 지시문을 잘 작성하는 기술을 연구하는 학문입니다.
>
> 우리 프로젝트에서는 프롬프트 엔지니어링과 검색 증강 생성(RAG, Retrieval Augmented Generation)을 활용하여 챗봇 서비스를 구현하였습니다.

#### Method

- 효율적인 Prompt를 만들기 위해서는 큰 가이드 라인이 필요하며 그 속에서는 세부적으로 조절해 나가야한다.

Prompt Engineering의 과정은 크게  3가지로 본다면 다음과 같다.

- Task Description은 모델이 수행할 작업에 관해 간단한 설명을 해준다.
- Examples는 모델이 수행할 작업을 몇 가지 예시로 보여준다.
- Prompt는 이를 통해 모델은 누락된 텍스트를 생성하여 완성한다.
- 문서를 가져오고, 분할하여 파싱한다. 이후 Dense Vector 형태의 embedding 을 진행하고 나중에 Retrieval 단계에서 빠르게 검색 후 사용할 수 있도록 저장한다.
- 프로세스 : 입력쿼리 또는 프롬프트를 받고 RAG를 활성화한다. \*문서를 검색하는데 검색리스트를 활성화하여 쿼리 처리한 후 문서를 가져오는 방법으로 retrieval 할 수 있다.
- 가져온 문서를 통해 Information Augmentation한다. 이를 통해 Context Integration이 진행되는데 원래의 입력과 문서에 얻은 정보와 맥락을 합하는 과정을 말한다.
- 이후 Language Model Generation이 이루어진다.
- 최종적으로 이를 Output에 전달한다.

#### Experiment

Open AI API를 통해 assistant를 생성한다

---

배역의 대사를 추출하여 Open AI API를 통해 작업을 진행하였으며,<br>목표, 배경상황, 지침을 지정하여 효율적인 답변을 뽑아낼 수 있도록 구현하였습니다.<br>하지만, 데이터 프로세싱 과정에서 중단이 되는 경우가 많았고,<br>실제로 원활한 학습이 되지 않는 경우도 많았습니다.<br>Open AI API로만 구현이 된다는 한계가 있습니다.

> ✍️ **Feedback**
>
> 언어 모델은 확률에 기반하여 단어를 반복적으로 생성하기 때문에 환각(hallucination)이 발생하는 문제가 있습니다. 그래서 등장한 기술이 RAG입니다. RAG는 언어모델이 응답을 생성하는 데 참고할 문서를 제시함으로써 환각을 줄이고 답변 정확도를 높이는 기술입니다. 우리는 이 데이터로 나무위키 문서와인물의 대사를 사용하였습니다.
>
> 두 데이터 모두 자동 수집이 가능하도록 하였으며, OpenAI의 assistant API를 사용하여 리트리버와 언어모델을 연결하였습니다. API를 통해 프롬프트에 대한 응답을 평가하면서 프롬프트 엔지니어링을 수행하였습니다.

#### Results

우리가 원하는 요청에 대한 정확하고 다양한 정보를 생성시킴으로써<br>정보의 품질과 다양성을 향상시키고 보다 효과적인 결과물을 제공하였다.

프롬프트 평가와 튜닝을 반복하며 높은 수준의 페르소나를 가진 챗봇을 완성할 수 있었습니다. (실험내용 보여주기)

#### Conclusion

Open AI API로 돌려본 결과 질문자의 의도에 맞게 성능이 좋은 챗봇을 만들 수 있었다.<br>모든 배우나 배역의 특성을 살릴 공통적인 Prompt를 원하는 완성도로 만들기는 어려웠지만 어느정도 성과를 거두었다.<br>하지만 Open AI API로 만들어야 한다는 명확한 한계가 존재했다.

---

좋아하는 작품의 주인공과 대화하는 챗봇 서비스를 기획하며,<br>사용자가 원하는 답변을 구현하기 위해 다양한 질문지를에 대한 싶도 있는 고민이 필요하였으며, 해당 챗봇이 소비자에게 어떠한 도움이 될지에 대한 방향성의 한계가 있었습니다.

RAG와 프롬프트 엔지니어링만을 통해 언어모델에 임의의 페르소나를 부여하고 대화를 주고받는 서비스를 개발할 수 있었습니다. 현재 서비스는 전적으로 OpenAI API에 의존하며 리트리버에 사용되는 PDF 문서를 임의로 편집하기 어렵다는 한계가 있습니다. 하지만 언어모델과 관련된 기술에 대한 지식을 전제하지 않고 간단한 방법으로 일반화된 챗봇 서비스를 구현할 수 있다는 점에 의의가 있는 프로젝트입니다. 코드는 github에 공개되어 있으며, 누구나 어렵지 않게 원하는 인물과 대화하는 챗봇을 만들어볼 수 있습니다.
